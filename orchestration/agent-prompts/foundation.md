## Retrieve first

Retrieve Bun 1.4.2 compilation, workspace, dynamic import and bun:sqlite documentation from https://bun.sh/docs; TypeScript compiler documentation for the chosen pin; AI SDK model/tool interfaces at https://ai-sdk.dev/docs for the exact compatible packages selected. Check package registry metadata and official release documentation before pinning. Read Telegram official shapes only as needed to keep C04 neutral. Do not guess API versions.

## Starting conditions

No implementation prerequisites. Recheck baseline and instructions, establish the permitted local Git workflow and compatibility probes. Encode the recorded administrator/reset/steering decisions when freezing their relevant types.

## Owned paths

Core types/config, workspace manifests/lock/build/CI/schema/provenance and initial dispatcher/fakes, with the recorded later transfers.

The authoritative ownership is execution-plan.md row F and its transfer rules. Edit only that assignment, including colocated tests; manifests/lockfile and other shared paths follow their named owner. Report ownership or contract discrepancies before editing affected files; continue unaffected work.

## Deliver

Bootstrap the workspace and minimal compiled entrypoint. Prove standalone loading of a dependency-free native tool with a local import. Pin dependencies/runtime, establish executable check/build commands and update testing.md with results. Freeze C01–C09 in code with conformance fixtures and migrate this document to code links. Generate config schema from its single authority. Provide minimal fake Gate/provider and prove C09 next-step continuation against the pinned SDK. Default the schema to steer, preserving queue as an option; C consumes that default in its templates. Set license/provenance policy. Integrate downstream handoffs without concurrent shared-file edits. Requirements and primary/supporting accountability are the F rows of the traceability table; source-linked acceptance criteria remain authoritative.

## Constraints

Do not implement complete runtime, storage or adapters under the guise of foundation. Keep CLI entrypoint lazy. Do not create a web framework or copy OAuth clients. Follow explicit transfer rules for fakes and dispatcher.

## Required validation

T01 plus schema/contract conformance and source import review. Run exact commands you establish, record runtime/pins and compiled artifact path. Unknown compatibility blocks consumers, not just a warning. Use commands established in testing.md and report exact results rather than assumed success.

## Handoff and definition of done

Publish verified base revision, code authority links for every C-ID, actual validation commands, pin rationale and transfer acknowledgments. This unlocks S/P/G; retain integration ownership per the plan. Include changed paths/interfaces, tests and validation output summary, remaining assumptions/blockers, and the revision needed by downstream owners.
