# Bun source distribution on Debian

Source revision: `5590eae` (`v0.1.0-preview.8` was the installed standalone baseline). The user explicitly asked to remove that roughly 88 MB executable and move normal installs and updates to separately installed Bun and dependencies. The standalone file at `/home/cami/.local/bin/vian` was removed after verifying it was an ELF; bot data and credentials were untouched. No daemon socket was active.

The installer had selected standalone because its `auto` branch looked only for Bun in `PATH`. Bun 1.4.2 already existed at `/home/cami/.bun/bin/bun`, but the noninteractive shell did not include that directory. The default is now the source archive. It finds pinned Bun in `PATH` or the standard user location; when needed it calls the official Bun installer for `bun-v1.4.2`. It verifies the archive against `SHA256SUMS`, installs production workspace packages with `bun install --frozen-lockfile --production`, checks the resulting CLI, and switches a versioned source tree. The small command wrapper reads the absolute Bun path, so a noninteractive shell and user service can run without a Bun `PATH` entry. An explicit `--runtime standalone` still selects the legacy binary.

The release workflow publishes `vian-source.tar.gz` with its checksum. The archive contains `package.json`, `bun.lock`, `install.sh`, `LICENSE`, and `packages/`, but no `node_modules` or embedded Bun runtime. Its local test build was about 118 KB. Bun's package cache avoids fetching unchanged packages on updates; each version still gets an isolated installation for rollback safety. The source updater invokes its local installer. The systemd unit points at the stable `current` source symlink so a service restart loads an update.

Dependency baseline: Bun 1.4.2 from `.tool-versions`; root/workspace manifests and `bun.lock` were read and unchanged. Official references retrieved 2026-09-29: [Bun installation documentation](https://bun.sh/docs/installation), documenting `https://bun.com/install`, pinned `bun-v1.4.2`, and `BUN_INSTALL`/PATH; [Bun install CLI documentation](https://bun.sh/docs/pm/cli/install), documenting frozen lockfile and production installs. No external code was adapted and no new package was added.

Validation before publication: `sh -n install.sh`, `git diff --check`, `/home/cami/.bun/bin/bun run typecheck`, and `/home/cami/.bun/bin/bun run check` passed at the working revision. The full check ran 130 tests. An isolated `file://` source archive install with Bun absent from `PATH` produced a working 199-byte `vian` wrapper and a 31 MB source/dependency tree without changing user bot data. Offline tests cover checksum rejection, source activation, repeated install, failed update preservation, and updater delegation. `b235109` was published as `v0.1.0-preview.9`; its release succeeded and included a 119,530-byte source archive, checksum, and optional standalone assets. The Debian host then installed preview.9 from the release and `vian update` reported it already current without downloading the archive again. A follow-up release adds Vian's MIT license to the source archive; Bun-installed dependencies carry their own package licenses.

Final publication and host update: `837d2c8` was pushed and tagged `v0.1.0-preview.10`. GitHub Actions Release binaries and Verify both completed successfully. On this Debian host, `/home/cami/.local/bin/vian update` upgraded the installed source from preview.9 to preview.10; `bun install --frozen-lockfile --production` reported 30 packages installed from the existing cache in 14 ms. The installed command remains a 199-byte POSIX shell script, `current/.vian-version` reads `v0.1.0-preview.10`, `LICENSE` is present, and `vian --help` passes. No daemon was running, so no restart or user-service change was needed. Live Telegram/model compatibility was not exercised by this packaging change.
