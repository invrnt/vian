# Bun source distribution on Debian

Source revision: `5590eae` (`v0.1.0-preview.8` was the installed standalone baseline). The user explicitly asked to remove that roughly 88 MB executable and move normal installs and updates to separately installed Bun and dependencies. The standalone file at `/home/cami/.local/bin/vian` was removed after verifying it was an ELF; bot data and credentials were untouched. No daemon socket was active.

The installer had selected standalone because its `auto` branch looked only for Bun in `PATH`. Bun 1.4.2 already existed at `/home/cami/.bun/bin/bun`, but the noninteractive shell did not include that directory. The default is now the source archive. It finds pinned Bun in `PATH` or the standard user location; when needed it calls the official Bun installer for `bun-v1.4.2`. It verifies the archive against `SHA256SUMS`, installs production workspace packages with `bun install --frozen-lockfile --production`, checks the resulting CLI, and switches a versioned source tree. The small command wrapper reads the absolute Bun path, so a noninteractive shell and user service can run without a Bun `PATH` entry. An explicit `--runtime standalone` still selects the legacy binary.

The release workflow publishes `vian-source.tar.gz` with its checksum. The archive contains `package.json`, `bun.lock`, `install.sh`, and `packages/`, but no `node_modules` or embedded Bun runtime. Its local test build was 118 KB. Bun's package cache avoids fetching unchanged packages on updates; each version still gets an isolated installation for rollback safety. The source updater invokes its local installer. The systemd unit points at the stable `current` source symlink so a service restart loads an update.

Dependency baseline: Bun 1.4.2 from `.tool-versions`; root/workspace manifests and `bun.lock` were read and unchanged. Official references retrieved 2026-09-29: [Bun installation documentation](https://bun.sh/docs/installation), documenting `https://bun.com/install`, pinned `bun-v1.4.2`, and `BUN_INSTALL`/PATH; [Bun install CLI documentation](https://bun.sh/docs/pm/cli/install), documenting frozen lockfile and production installs. No external code was adapted and no new package was added.

Validation before publication: `sh -n install.sh`, `git diff --check`, `/home/cami/.bun/bin/bun run typecheck`, and `/home/cami/.bun/bin/bun run check` passed at the working revision. The full check ran 130 tests. An isolated `file://` source archive install with Bun absent from `PATH` produced a working 199-byte `vian` wrapper and a 31 MB source/dependency tree without changing user bot data. Offline tests cover checksum rejection, source activation, repeated install, failed update preservation, and updater delegation. Published release and real host source installation remain to be recorded after release.
